# 状态图生成提示词模板（ImageGen 图生图）

用 1 张真实宠物照片派生多状态图时，按本文档拼接提示词：**通用约束 + 身份风格 + 单个状态描述**，配合原图做 image-to-image，一次只生成一个状态。

## 生成纪律（实测踩过的坑，必读）

- 成本：每张约 5-10 积分，全套 6 张约 30-60（重试另计）；生成前报张数和预估积分，征得用户同意。
- 顺序：先生成 idle 与用户确认风格和相似度，满意后再批量出其余状态。
- **必须串行生成，不要并行调用**：ImageGen 输出文件名由"提示词前缀 + 秒级时间戳"构成，并行会同名互相覆盖（已实测一次并行丢 3 张）。每张生成后立即重命名为 `<状态>-raw.png` 再生成下一张。
- **姿势类状态要下猛药**：wave 这类带明确动作的状态，把动作描述放在"状态要求"最前面并强调"必须满足"+ 负面约束（如"不要趴着"），否则模型容易忽略动作（已实测：只写"抬起一只前爪"时模型照趴不误，强化后一次通过）。
- 逐张过目：身份漂移大、构图不统一或姿势不符的单张重试，不要不确认就整批用掉。
- 抠图：全部确认后用 `scripts/remove_bg.py` 统一抠图（需 Pillow venv），抠完再给用户过目一轮透明底效果。
- ImageGen 参数建议：`input_fidelity: high`（保身份）、`size: 1024x1024`、`quality: high`；身份提示里写清花色特征（如"黑白奶牛猫，背黑、胸口和爪子白"）。

## 通用约束（每张图提示词的开头）

构图统一，主体大小统一，保持与其他状态图一致的视角和比例。主体尽量居中，留出少量边距。适合做桌面宠物 PNG 素材。纯色浅背景，方便抠图。

## 身份与风格要求（接在通用约束之后）

根据上传的真实宠物照片，生成同一只宠物的桌面宠物状态图。要求保持和参考照片一致的宠物身份特征，包括毛色、花纹、脸型、耳朵、眼睛、体型与整体气质。风格为比较写实的数字插画，接近真实宠物，但画面要干净、可爱、适合做桌面宠物素材，不要过度卡通，不要夸张Q版。宠物主体清晰，单独呈现，完整或接近完整的身体，构图居中，边缘干净，适合后期抠图或透明背景使用。不要复杂背景，不要家具，不要场景，不要其他动物，不要多只猫，不要文字，不要水印。整体风格参考"写实可爱桌面宠物"，情绪表达清晰，但身体结构仍然保持真实宠物的自然状态。

## 各状态描述（每张图取一个接在最后）

| 状态 | 描述 |
|------|------|
| idle | 宠物自然站立或端坐，表情平静，微微看向前方，呈现默认待机状态，姿势放松，安静可爱。 |
| rest | 宠物进入休息状态，趴下或蜷缩，眼睛半闭或闭上，神态放松，像是在打盹，整体感觉温柔、安静、困倦。 |
| curious | 宠物注意到前方的动静，眼神更专注，耳朵稍微竖起，头部略微抬起，呈现"被吸引、好奇、正在看你"的悬停交互状态。 |
| happy | 宠物表现出被点击后的开心反应，神态更活泼，眼神明亮，可以微微张嘴，身体略微前倾，呈现亲近、愉快、被互动后的可爱反馈。 |
| excited | 宠物做出更明显的互动反应，表现出惊喜或兴奋，眼睛更有神，动作比普通点击更明显，可以轻微抬起前爪或身体微微跃起，整体感觉灵动、开心、互动感强。 |
| wave | （最重要，必须满足）宠物端坐着，一只前爪明显抬起、举在空中伸向斜上方，像在跟人打招呼说嗨，另一只前爪撑地，神态友好，表情灵动，带一点互动感，但整体依然保持真实宠物的自然动作，不要过度拟人化，不要趴着。 |

## 状态 → interactions 推荐映射

构建 spec 时按下表把状态绑到触发；一个触发可配多条台词（运行时随机抽）：

| 触发 | 状态（按推荐顺序） | 说明 |
|------|------|------|
| rest | rest、idle | 打盹与发呆轮换 |
| hover | curious、wave | 悬停时好奇看你或打招呼 |
| click | happy | 被点击的开心反馈 |
| doubleClick | excited | 比单击更强烈的兴奋反馈 |

只生成 4 张基础款（idle/rest/happy/wave）时：curious 缺图自动复用 idle，excited 缺图自动复用 happy（build_pet.py 会处理并在 warnings 里说明）。
